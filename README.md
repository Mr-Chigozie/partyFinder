# Party Finder

> Don't spend your weekend wondering where the fun is. Find your vibe, find your people, and go.

A social party finder, not another ticketing site. Open it on a Friday at 7pm with no plans and see what's happening tonight, how lively each place is right now, and who's going.

This is a clickable prototype using demo data for Abuja (all venues and people are fictional).

## Run it

No build step. Serve the folder with any static server:

```sh
npx http-server -p 8080
# or: python -m http.server 8080
```

Then open http://localhost:8080. Opening `index.html` directly also works, but map tiles may not load from `file://`.

## Sign-up and onboarding

New visitors land on a split-screen login page: the form sits on the left, and two original illustrations fill the right half (a neon VIP booth and a dance floor). After creating an account (name, email or Nigerian phone number, password, date of birth with an 18+ check), users go through 5 onboarding steps:

1. **Your scene**: event types (rooftops, club nights, outdoor and picnics, owambe, comedy…)
2. **Your sound**: Afrobeats, Amapiano, Street-pop, Alté, Fuji…
3. **Your vibe**: what they want from a night, usual spend, solo or squad
4. **Your city**: city (Abuja is live, others are on a waitlist), home area or GPS, travel radius, nights out
5. **Your rules**: privacy and notification toggles (sharing is off by default)

A live preview next to the questions re-ranks tonight's events as answers change. The answers feed `matchEvent()` in `data.js`, which scores every event from 0–100 by type, music, budget, distance and vibe. That score drives the **For you** sort and the "92% match · Because you like…" labels in the feed. To change answers later, use the avatar menu → *Edit my vibe*. A guest account is available on the login page for quick testing.

> Prototype auth: accounts are stored in this browser's `localStorage` with a hashed password. This is **not** secure for production. Real launch needs a backend (sessions, OTP for phone sign-up, password reset).

### Artwork

`assets/lounge.svg` and `assets/crowd.svg` are original, generated by `node tools/make-art.mjs`, so the project owns them outright. To swap in licensed photos later, point the two `<img>` tags in `auth.js` (`.vis-a`, `.vis-b`) at your files.

## What's in the prototype

| Feature | Where | What it does |
| --- | --- | --- |
| **Tonight feed** | 🌙 Tonight | Events happening now and later, sorted *for you* (onboarding match), *soonest*, *nearest* or *hottest vibe*. Filters for category, budget, free-only and friends-going. Ended events sink to the bottom. |
| **Live Vibe Map** (core) | 🗺 Vibe Map | Pins coloured by live vibe score. Live events pulse and ended ones fade. Tapping a pin opens the event. |
| **Live Party Stories** | Feed strip + event sheet | Venues (✔ verified) and attendees post short updates with a crowd level and vibe rating. The vibe score is the average of updates from the last 2 hours, falling back to the organiser's estimate. |
| **What's the Plan?** | 💬 Plans | Post "Budget ₦15k, Afrobeats, around Wuse". Others reply, suggest an event or tap *I'm in*. The app auto-suggests spots that fit the budget, genre and area. |
| **Find Your Crew** | 👯 Crews + event sheet | Create a group plan for an event, invite friends, set a size limit and choose whether strangers can join. Browse open crews. |
| **Event details** | Tap any event | Entry fee, dress code, times, distance, directions, friends going, people looking for company, crews and stories. |

Privacy is opt-in: *I'm going* can be hidden from friends, and *Looking for company* is a separate, explicit toggle.

Your actions (going, plans, crews, stories, replies) are saved in `localStorage`, so they survive a reload. Demo event times are generated relative to when you open the page, so something is always "live".

### Monetisation hooks (placeholders)

- **Promoted** badge on paid placements (`promoted: true` in `data.js`).
- **Get tickets** → ticket commission.
- **Book a table** → reservation referral fee.
- Verified venue badge → part of a venue subscription.

Browsing and the social features stay free.

## Files

- `auth.js` / `auth.css`: login, sign-up and onboarding
- `assets/`: login illustrations (`tools/make-art.mjs` regenerates them)
- `index.html`: app shell and tab bar
- `styles.css`: dark, mobile-first styling
- `data.js`: demo venues, events, stories, plans and crews
- `app.js`: state, rendering, filters, map and actions

## Next steps toward a real product

1. **Backend + auth**: accounts, a friends graph (phone contacts / invite links), real persistence (e.g. Postgres + PostGIS for geo queries).
2. **Real-time**: push story updates and vibe changes over WebSockets, and send notifications when friends commit to a plan.
3. **Venue tools**: verification flow, event creation, story posting from venue accounts, analytics dashboard (subscription tier).
4. **Trust & safety**: phone verification, reporting/blocking, women-only crew options, moderation of stories, "share my location with my crew" for the night.
5. **Payments**: Paystack/Flutterwave for tickets and table deposits.
6. **Mobile app**: React Native / Flutter once the core loop is validated.
